Choosing a Region

  3. Services — not all services available in all regions

Examples

EC2AWS: physical host → You: OS, apps, security groups
RDSAWS: OS + DB engine → You: data, access, backup config
LambdaAWS: infra + runtime → You: code + IAM permissions
S3AWS: infra → You: bucket policies, encryption, public access

IAM — Identity & Access Management

Userindividual identity with credentials
Groupcollection of users; attach policies to group not individual
Roleidentity for services or cross-account access; no passwords
PolicyJSON document defining what's allowed or denied
Access KeyCLI/SDK auth; ID + secret pair; never share

Best Practices

  1. Enable MFA on root and all users
  2. Never use root account for daily tasks
  3. Least privilege — only give permissions needed
  4. Use roles instead of sharing credentials
  5. Rotate access keys regularly

6 R's of Migration

Rehostlift & shift — move as-is; quickest, least effort
Replatformlift, tinker & shift — minor optimizations (e.g. switch to RDS)
Repurchasedrop & shop — move to SaaS (e.g. Salesforce, ServiceNow)
Refactorre-architect for cloud-native; most work, most long-term benefit
Retiredecommission what you no longer need
Retainkeep on-prem for now; not ready or not worth migrating
